# 长文精炼

长文整理只使用用户指定的 `gpt-6.1-sol`，思考强度固定为 `low`，通过服务器 Codex CLI 调用。模型不可用时保留原文和失败状态，不换模型、不自动重试，也不把截断的原文当作读完。

## 输入与输出

根调度程序执行 `deploy/summarize-run.sh`，不传命令行参数，通过标准输入发送一个 JSON 对象：

```json
{"source_url":"https://example.org/article","title":"原文标题","text":"完整原文","content_hash":"原文UTF-8字节的SHA-256十六进制小写值"}
```

`content_hash` 必须由未经再次裁剪、替换或去空格的 `text` 计算。来源地址只供父调度程序保留出处，不会传给模型。CLI 读取的是标题和原文文本，不会自行打开网页。

输出字段：

```json
{"status":"ok","summary":"两至三句中文摘要。说明核心进展及限制。","body":"待审核的中文正文","model":"gpt-6.1-sol","reasoning":"low","content_hash":"原文哈希","usage":{"input_tokens":0,"output_tokens":0}}
```

只有 `ok` 或 `cached` 可以作为审核稿候选。其他状态不覆盖已有正文：

| 状态 | 含义 |
|---|---|
| `ok` | 本次模型输出通过本地格式检查 |
| `cached` | 原文已有合格缓存，本次没有调用模型 |
| `skipped_short` | 原文不超过 2000 字，不调用模型 |
| `too_long` | 原文超过 20000 字，留待人工处理，不截断 |
| `cooldown` | 原文或服务处于六小时冷却期 |
| `error` | 输入、模型、权限或输出检查失败 |

字数按 Python Unicode 字符数计算。摘要 20–180 字，中文两至三句；正文 80–1800 字，给父程序附出处后不超过 2000 字留出空间。父程序仍需检查最终总长，并负责仅更新未被人工编辑的待审自动稿。字数和 JSON 通过不代表事实已核验，发布仍需站长审核。

## 调用边界

包装命令仅接受 root 调度账号或 `infogap-agent`。root 会切换到 `infogap-agent`，使用清理后的环境；站点账号没有 sudo 权限。整理账号不读网站数据库、SMTP 或支付密钥。程序本身不连接数据库，也不发布内容。

Codex 使用只读沙箱、独立临时工作目录、临时会话模式和严格 JSON 输出 schema。关闭命令执行、多代理、MCP、应用、插件、浏览器、图片工具、技能发现和网页搜索。模型输入明确将原文视作资料，原文中的命令、角色设定和登录要求不构成操作授权；若 JSONL 中出现工具调用，结果会被拒收。

每篇最多等 120 秒。超时会终止整个子进程组，不追加重试。服务或指定模型失败时暂停新调用六小时；某篇输出校验失败时，该原文单独暂停六小时。父调度程序另外限制每批、每日处理数量。

## 缓存与用量

默认缓存目录为 `/var/lib/infogap-agent/summaries`，权限 0700，文件 0600。缓存键由原文哈希、固定模型、思考强度和提示词版本组成。只缓存整理结果、有限用量字段和错误状态，不缓存完整原文或凭据。重复的合格内容直接返回 `cached`，本次 `usage.model_calls=0`，旧用量放在 `original_usage` 中。

目录锁防止同一账号并行发起多个整理请求。缓存先写临时文件再原子替换。模型服务处于冷却期时，已有合格缓存仍可读取。

## 验证

离线测试位于 `scripts/summarize-test.py`，使用临时目录和模拟进程，不访问真实模型。覆盖字数边界、哈希检查、缓存命中、原文变化、六小时冷却、输出含链接或 HTML、工具调用拒收、环境隔离、超时终止和并发锁。

2026-10-21，服务器指定模型的连通测试返回 `INFOGAP_READY`。随后通过实际降权包装命令整理了一篇中国政府网 4684 字原文：返回 `ok`，摘要 109 字、正文 758 字，保留了“先使用后付费”“中小微企业”、核聚变与脑机接口等原文事实，并区分政策方向与已落地效果。第二次提交同一原文返回 `cached`，`model_calls=0`。测试未写站点数据库、未发布内容、未改变默认模型或网关配置。

本次成功调用报告输入 17128 tokens、输出 616 tokens；CLI 自带上下文仍有固定开销，低思考强度并不等于零输入成本。缓存、短文跳过和批次限制用于减少重复调用。17 项离线测试通过，另核对了 Python 3.6 语法和包装脚本语法。实测摘要见 `docs/summarizer-verification.json`。

CLI 0.163.0 会把配置或弃用警告输出为 `item.completed/type=error`；这些提示不等于工具调用。解析器兼容此格式，但顶层错误、失败结束、模型被切换以及实际工具调用仍拒收。完整队列与上线后稿件验收由父调度程序完成。

官方调用方式参考：[Codex 非交互模式](https://developers.openai.com/codex/noninteractive)。本项目使用服务端实际支持的 `exec`、`--ephemeral`、`--json` 和 `--output-schema` 参数。


## 站点调度与后台

`infogap-summary.timer` 每六小时检查队列，每轮最多处理3篇，每个北京时间自然日最多8次，单篇最多尝试3次。只有自动采集的待审稿可进入队列；短文不调用模型，超长或被截断的原文交人工处理。同一来源、同一原文不会反复入队。

父进程调用模型前后都会核对稿件状态和编辑记录；一旦有人编辑、发布、驳回或证伪，就保留人工处理结果。成功稿件仍为待审核，不触发内容发布、用户奖励或等级提升。站长后台可以查看等待、已整理、需处理、整理中和保留人工修改的数量。
