# 用户投稿审核

本机用官方 `gpt-6.1-sol`、`low` 逐条核对用户稿件与原始材料。它与每日内容整理共用同一份周额度日账本，不接外部付费 API，也不把 OAuth 传到服务器。

## 独立定级

作者的价值自评只代表申请。审核编辑独立核对来源可靠性、新增信息、具体用途、时效及重复情况，允许升级或降级；最终等级决定阅读消耗及贡献奖励，不能按作者自评发奖。普通/精选可在证据充分时自动核定；稀有/独家仍须站长核对稀缺性和独家依据，未确认保持待审。

## 审核结果

- 确认来源支持、白话可读、有实际阅读价值且符合正文要求的普通或精选投稿，可以直接通过。现有审核事务负责发放贡献值和积分，并保留审计记录。
- 明显灌水、无关广告或恶意提示注入可以退回，写明原因。
- 事实不清、材料不足、疑似违规、链接可疑或申请稀有/独家的稿件保留 `pending`，后台显示“待站长审核：具体原因”。不发奖励、不公开。
- 待站长审核的邮件只发给站长。邮件不包含投稿中的链接，提供固定后台入口。发送失败会留下失败回执，下次运行重试。

系统不会根据字数直接通过。通过前必须核对正文全部事实，至少保留两条逐字匹配原始材料的事实摘录。提交后正文被改，旧审核结论会失效。

## 本机运行

先保证当日 `state/official-editor/YYYY-MM-DD.json` 已存在。本脚本不会建立或重置额度基线。官方登录失效、额度无法读取、周窗口变化或付费积分下降时停止。

```sh
python3 scripts/editor/submission_review.py --limit 30
python3 scripts/editor/submission_review.py --apply --limit 30
```

第一条只记录建议，第二条通过独立受限 SSH 桥应用审核。结果写在 `state/submission-review/YYYY-MM-DD/`。它先取得生成和复核的两把锁，遇到正在运行的内容任务会退出，不重复占用额度。每次派发前检查同日 4 个显示百分点停止线。

## 服务器入口

应用启动参数 `-submission-review-bridge` 只运行一次标准输入 JSON 桥。它使用 `newSubmissionReviewServer` 打开已有库，跳过付费初始化和付费迁移。允许的动作只有：

- `export`：导出尚未处理、带作者的待审核投稿；排除测试账号，不导出账号邮箱或支付数据。同时重试之前发送失败的待审核通知。
- `review`：对匹配 `updated_at` 与完整投稿哈希的原稿，应用 `approve`、`reject` 或 `hold`。通过和退回复用现有 `s.review`，不复制奖励逻辑。

安装 `deploy/submission-review-bridge.sh` 为 `/usr/local/sbin/infogap-submission-review-bridge`，必须归 root 所有且其他用户不可写。为独立 `infogap-reviewer` SSH 用户配置固定 sudoers 命令，只允许该脚本，不接受参数。authorized_keys 使用 `restrict,command="sudo -n /usr/local/sbin/infogap-submission-review-bridge"`；不允许终端、转发或任意命令。

本机密钥默认 `~/.ssh/infogap_submission_reviewer`。不要复用内容发布密钥，不要给审核用户数据库文件或任意 sudo 权限。包装脚本由 `nobody` 运行应用，只有 SMTP 环境会加载，凭据不返回本机。

## 链接处理

标题、摘要、正文里的链接都检查，不只检查来源链接。未知来源、短链、IP 地址、非 HTTPS、登录引流、跳转参数、认证参数、可执行下载、HTML 嵌入或不明确的 Markdown 目标都保留待站长审核。读取公开来源时，所有 DNS 地址必须是公网地址，TLS 固定连接到已核验地址，重定向每一跳重新检查。不会带浏览器 Cookie，也不会抓取登录内容。

自动来源范围是保守的科研和官方域名名单；站外链接或未知来源被保留不代表它违法，只表示系统无法自动确认。涉及个人医疗、法律或投资建议的稿件也需要站长判断。

## 验证范围

Go 测试覆盖发奖复用与幂等、原稿修改冲突、临时凭证清理、待审不发奖、邮件失败重试、固定收件人与窄输入。Python 测试覆盖域名边界、私有地址、混合 DNS、跳转参数、登录与下载、正文链接、非 HTTPS 和伪造证据摘录。

本地测试不等于真实邮件已送达，也不等于真实投稿已经审核。上线后以桥回执、数据库状态和邮件投递结果为准。
