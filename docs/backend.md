# InfoGap 后端

使用 Go 1.26 和 SQLite，账号、会话、投稿、解锁记录和额度流水存入同一个数据库。SQLite 启用 WAL、外键和 10 秒 busy timeout；账户与内容变更通过事务执行。

## 启动

```sh
go test ./...
go build -o /tmp/infogap .
INFOGAP_PUBLIC_URL=http://127.0.0.1:18869 /tmp/infogap -addr 127.0.0.1:18869 -db state/infogap.sqlite -web web
```

生产环境设置 `INFOGAP_PUBLIC_URL=https://infogap.osh.lol`，服务只监听本机端口，由反向代理提供 HTTPS。代理设置 `X-Real-IP`；应用仅信任回环代理提供的该请求头。不要将服务端口直接暴露到公网。

SMTP 参数通过环境注入：`SMTP_HOST`、`SMTP_PORT`、`SMTP_USER`、`SMTP_PASSWORD`、`SMTP_FROM`、`SMTP_SECURITY`。465 端口默认使用 TLS，其余端口默认 STARTTLS，必须验证服务端证书。仓库不保存真实参数。

## 账号与权限

新成员必须持有有效邀请码并验证邮箱。唯一站长邮箱为项目指定邮箱，只有该邮箱验证码验证成功后才创建站长账号。管理员接口不能创建第二个站长，也不能停用站长。

验证码 10 分钟有效、最多尝试 5 次。同邮箱发送间隔至少 60 秒，同来源 IP 每小时最多 10 次，全站每小时最多 100 次。验证码不会出现在响应或日志。服务重启会使未使用验证码失效，用户需重新获取。

会话有效期 30 天，数据库仅保存会话令牌摘要。生产 Cookie 使用 Secure、HttpOnly 和 SameSite=Lax。成员写接口要求 JSON，并检查 Origin 和 Sec-Fetch-Site；唯一例外是 `POST /api/billing/notify/huifu`，由支付模块独立验签并核对订单、商户和金额。停用账号立即撤销其会话。

## 阅读与贡献

新注册账户初始永久积分为 0，既有账户余额保持不变。按黑铁到王者段位，每天分别赠送 1/2/3/5/8/10/15/20/30/50 点，北京时间零点刷新，不累计。普通/精选/稀有/独家分别花费 1/2/4/8 点，先扣当日额度，再扣即将到期的段位赠分，最后扣永久积分。解锁记录与扣减在同一事务内提交，重复或并发请求只扣一次。旧版周额度字段仅保留兼容，不再参与计算。指定活动邀请码的名单内新成员可获得一次性永久积分和限时青铜权益；活动权益不产生段位每期赠分，详见 `invite-campaigns.md`。

稀有内容要求白银段位与精选贡献记录。独家内容要求钻石段位、稀有贡献记录，以及最近 90 天的高质量贡献。作者、站长和审核员可以阅读内容全文。

投稿须含来源、摘要和正文，通过审核后一次性奖励 100 点长期额度。审核员不能审核自己的投稿；稀有、独家级审核必须填写核验依据。被证伪内容停止新解锁，并退回阅读者实际支付的长期额度；当日额度仅在原消费日内退回，过期不转成长期额度。重复操作不重复退款。审核员确认信息被证伪后，撤销该条奖励积分和贡献资格，并从作者现有余额收回最多 100 点奖励额度；余额不足时归零，不形成负数。系统记录实际扣除数量，重复证伪不重复撤销。自然过期不撤销贡献奖励。

管理员与审核员可通过 `POST /api/admin/gaps/{id}` 整理候选稿。字段为 `title`、`summary`、`body`、`category`、`evidence`、`tags`，来源不可更改。保存后回到待审核，旧版内容保存在审计记录中；原先已解锁的成员保留访问权限。证伪记录不允许覆盖，应另建更正稿。

## 段位时效

内容从首次审核通过时间 `released_at` 开始计算开放时间。黑铁、青铜、白银、黄金、铂金、翡翠、钻石的延迟依次为 72、48、24、12、6、3、1 小时，大师及以上立即可见。管理员、审核员、作者和已解锁该条信息的成员不受延迟影响。付费会员不缩短延迟。

服务器在列表、搜索、收藏、订阅、详情和解锁操作中统一执行时效限制；未到时条目不出现在计数中，猜测其详情地址返回 404。管理员可用 `GET /api/gaps?status=all&page=1` 查看全部状态，或指定 `pending`、`published`、`rejected`、`expired`、`disputed`。后台概览包含最近 200 条全状态内容。

`published_at` 仅表示原始来源发布日期，不知道时为空；`created_at` 是本站入库日期，不能代替来源日期。最新排序以 `released_at` 为先。编辑后重新审核保留首次发布时间。启动迁移为旧版已公开数据使用入库日期补齐首次发布时间；已有明确日期保持原值。首批人工核验的历史种子可使用来源原日期，日常采集候选仍须从正式审核通过时计时。

## 订阅与会员

用户对象含 `membership_until`、`is_member` 和 `entitlements`，后者包括 `subscriptions`、`subscription_limit`、`delay_hours`。黄金可订阅 3 条标签或领域，铂金与翡翠 8 条，钻石 20 条，大师及以上 40 条。有效会员至少 20 条，站长 40 条。会员与段位均不影响基础搜索、收藏功能。

`GET /api/subscriptions` 返回 `{items,limit,enabled}`，每项包括 `id`、`kind`、`value`、`created_at`、`active`。`POST /api/subscriptions` 接收 `{kind,value}`，`kind` 为 `category` 或 `tag`；`DELETE /api/subscriptions/{id}` 删除本人订阅。添加与删除都检查当前权益，重复添加不占用新名额。`GET /api/gaps?view=subscribed` 仅匹配生效订阅，并保留正文解锁和时效限制。

会员到期或段位下降会保留配置，按创建顺序仅启用当前名额内的订阅；没有权益时暂停全部订阅。站长可通过 `POST /api/admin/users/{id}` 的 `membership_days` 延长功能会员，0 表示撤销，其他值为 1–3660 天；有效期内从原到期时间续期。付费及手动续期均不改变贡献积分、解锁余额、稀有门槛或时效。权限变更保存审计。

## 数据源

`schema.go` 中 `gaps` 和 `sources` 表与 `API.md` 约定一致。采集器只插入待审核内容，不自动发布、不奖励贡献。`source_url` 唯一，防止重复导入。种子数据由部署流程另行审阅并导入。

### 内部社区来源（1.0.1）

`gaps.source_visibility` 为 `public` 或 `internal`，默认 `public`。站长与审核员始终保留完整出处；内部来源对其他成员隐藏 `source_name`、`source_url`、`review_note`，包括投稿者和已解锁成员。标题、摘要、正文和标签也会清理来源名称、域名与对应链接；可独立核验的其他公开链接保留。普通搜索和标签订阅匹配清理后的文字，避免从搜索命中推断内部出处。

Linux.do 及其子域的用户投稿自动设为内部来源、待核验和待审核。启动迁移补充字段并将旧库中的同类来源设为内部；其他旧内容保持公开。采集器需显式写入同样的标记。

管理员编辑接口新增可选 `source_visibility` 字段，省略时保留原值，修改记录进入审计。内部稿发布前检查标题、摘要、正文与标签中的来源名称和域名残留，包括 Linux.do、LINUX DO、LinuxDO 别名及常见编码形式；检测到残留会要求先编辑整理。隐去社区出处不会把未核验内容自动升级为已证实内容，原始出处与核验说明仍留在后台。

## 检查

`server_test.go` 覆盖站长验证、一次性邀请、验证码错误次数、锁定正文不泄露、并发解锁、周额度、段位权限、奖励与退款幂等、自审拦截、管理员越权、CSRF 和禁用会话。`subscriptions_test.go` 覆盖权益、并发限额、到期、降级和迁移。`timing_test.go` 覆盖开放边界、全部读取路径、已解锁复看、管理员完整可见与首次发布时间迁移。`integration_test.go` 校验支付回调例外不扩散到其他路径，并核对来源时间和最新排序。

`source_privacy_test.go` 覆盖访客、成员、投稿者、已解锁成员与审核人员的来源隔离，以及搜索/订阅反推、内部稿发布检查、公开证据链接保留、字段迁移和可见性变更审计。

`/healthz` 返回数据库连通性、版本及 `commit`；发布时可通过 `-ldflags '-X main.buildCommit=<gitsha>'` 注入 Git 版本。它不返回账号、邮件配置或敏感数据。后台保留审核和权限变更审计，用户可查看自己的额度流水。支付接入与验签细节见 `docs/billing.md`。
