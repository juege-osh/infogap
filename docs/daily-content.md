# 每日内容更新与旧稿完善

目标：北京时间09:00—20:00每小时一批，累计约1000篇/日。每日末尾发布不足时报告差额，不用旧闻重复、模板扩写或无事实依据内容补足。

## 执行

本机官方账号登录与外接盘均须可用。模型固定 `gpt-6.1-sol`、`low`，生成过程没有浏览器、终端或其他工具权限。不读取外部API密钥，不复制OAuth到服务器。

1. 读取 `state/official-editor/YYYY-MM-DD.json`。每天最多5个官方每周总额度百分点，按北京时间记账，4个显示百分点停止新请求并预留1点。新稿、旧稿、重试共用同一基线；官方额度缺失、周窗口变化、积分余额下降即停机。整数计量和在途任务意味着这是一项保守的派发限制，不能保证精确小数百分比。
2. 在09至20点，累计目标为 `min(1000,84*(小时-8))`，执行 `python3 scripts/editor/daily.py --target 目标`。当天队列断点续跑，跨任务有文件锁。抓取结果保留在 `state/daily-content/YYYY-MM-DD/raw`，只收录7天内的来源订阅内容，来源地址与内容去重。来源日期不是首次发表时间，也不是政策生效时间。
3. 模型生成材料充足标记及300—1000字正文，通过格式与中文校验后，仅进入网站待审核队列。不得将“生成成功”报告成“已上线”。
4. 生成完成后，可执行 `python3 scripts/editor/review_queue.py --run-dir state/daily-content/YYYY-MM-DD --limit 累计目标` 做独立证据对照。审稿使用同一指定官方模型与每日额度，源文引用必须逐字存在；与生成使用各自的防重锁，共用同一每日基线与派发阈值。结果只写 `reviews.jsonl`，不会自动发布，失败或无法支持的仍待审。定时编辑员逐条核对来源与正文。核验事实、数字、因果、适用地区、例子与建议的界线、原文类型、预印本/修订，以及具体阅读价值。不能仅靠字数或usable标记发布。内容无充分依据或没有可解释价值则保留待审核，列明原因。
5. 对已核验条目，用 `from daily import bridge` 调用 `publish_reviewed`，每条传入 `id`、当前 `expected_updated_at`、正文SHA256的 `expected_body_hash`、不少于20字的具体审核说明 `review_note`。例如逐条说明核查了哪些结果与边界。只支持无个人作者的自动候选；状态冲突自动跳过。新发布默认普通级，不凭数量标精选或独家。
6. 回读桥接及线上API核对发布状态、正文、编号和权限。当天20点汇总：采集、生成、待审、发布、缺口、额度前后值及故障。无变化时不重复通知。

可用桥接请求：`export`（仅内容和整理队列）、`apply`（带乐观锁的旧稿修订）、`import`（只导入待审核）、`publish_reviewed`（审核后公开）。本机使用专用SSH密钥，服务器强制执行固定内容桥接程序。该账号不允许终端、端口转发或直接操作支付、成员、验证码和邀请码。

## 运行限制

这是本机定时工作：Mac需开机、联网，Codex已登录，外接盘挂载。休眠离线期间不能保证按小时完成。服务器普通爬虫仍运行，旧的外部API精炼定时器已停用，防止重复调用与覆盖；重新启用前需确认本机任务已停止并重新核算预算。
